  • Debian ServerDebian 12 / Compute & server workloads

    Runs Prominence II. Managed over SSH with CPU, memory, and process monitoring in htop.

  • Raspberry PiRaspberry Pi 4 / Pi-hole & local DNS

    Handles DNS queries and domain filtering. Administered over SSH, separately from the server.

Why this setup? Compute-heavy workloads stay on Debian; lightweight network services stay on the Raspberry Pi.

Technical detail

DNS resolution and service reachability are separate checks. Resolving a name does not confirm that the service itself is reachable.

04 / Operations

Running the lab.

Linux administration

SSH, service/process management, and CPU/memory checks with htop.

Technical detail

Process-level readings in htop help distinguish a busy server process from overall host pressure. These are live checks rather than historical monitoring.

Real workload — Prominence II

A demanding multiplayer server provides practice with memory allocation, CPU/resource management, server processes, and connectivity.

Why this workload? A multiplayer server makes resource usage and service behavior observable.

Technical detail

playit.gg provides player connectivity to the Prominence II server. The operations capture shows the tunnel client alongside the running workload.

Network services — Pi-hole

The Pi-hole dashboard shows DNS queries, filtering, blocklists, and client activity on the home network.

Why a separate Pi? DNS stays independent from heavier workloads on the main server.

Technical detail

Filtering happens at the DNS/domain level. Blocked-query information helps distinguish filtering from other connectivity problems.
